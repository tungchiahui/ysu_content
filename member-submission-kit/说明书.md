# 燕鹰战队个人资料填写教程（27赛季）

这份教程用于填写网站“成员”页面的个人资料。学生和指导老师都提交 Markdown 文件与头像。下面先以 **2027 赛季** 为例介绍基础写法；参加或指导过多个赛季时，在同一份档案中逐年记录。

## 第一步：选择模板并改名

| 身份 | 使用的模板 | 参考示例 |
| --- | --- | --- |
| 学生 | [成员资料模板](成员资料模板.md) | [学生示例](#学生怎么填) |
| 指导老师 | [指导老师资料模板](指导老师资料模板.md) | [老师示例](#指导老师怎么填) |

1. 下载或复制对应模板，用记事本、VS Code 等纯文本编辑器打开。
2. 把文件改成自己的真实姓名，例如 `张三.md`。
3. 保存为 UTF-8 编码，确认后缀是 `.md`，不是 `.md.txt`，也不要另存为 Word 或 PDF。

一人一份文件。文件名必须与下面的 `name` 完全一致；不以“张三”“老师姓名”等示例名字提交。

## 第二步：填写开头的资料区

文件最上方用两行 `---` 包围的部分是资料区；结束的 `---` 后面可以写个人介绍。保留英文键名，只修改右侧的内容。

- 冒号使用英文 `:`，冒号后留一个空格。
- 缩进使用空格，每一层两个空格，不要使用 Tab。
- 保留两行 `---`，不要删除 `seasons` 下方的短横线。
- 年份写四位整数，不加引号。**27赛季写 `2027`，不要写 `27` 或 `2027赛季`。**

### 学生怎么填

下面是一份普通队员的完整资料示例，可以复制后修改：

```markdown
---
kind: student
name: 张三
image: /images/member_photo/张三.jpg
affiliation: 机械工程学院
grade: 2026
seasons:
  - year: 2027
    group: 机械组
    roles: [成员]
---

## 个人介绍

这里写自己的学习方向、参与的工作或个人兴趣。

## 项目与比赛经历

- 按自己的实际经历填写，没有相关经历时可删除这一节。
```

| 字段 | 填写方法 |
| --- | --- |
| `kind` | 学生固定写 `student` |
| `name` | 真实姓名，与文件名一致 |
| `image` | 头像路径，写法见第四步；没有头像时删除这一整行 |
| `affiliation` | 实际所属学院，不填写学校名称 |
| `grade` | 自己的入学年份；示例中的 `2026` 要按实际情况修改 |
| `seasons` → `year` | 实际参加的赛季年份，如 `2027`；不是入学年份，多赛季逐条填写 |
| `seasons` → `group` | 从下面五个组别中选一个 |
| `seasons` → `roles` | 按实际职务填写列表，普通队员写 `[成员]` |

**组别只使用以下五种名称：**

| 组别 | `group` 的填写值 |
| --- | --- |
| 机械组 | `机械组` |
| 电控组 | `电控组` |
| 硬件组 | `硬件组` |
| 算法组 | `算法组` |
| 运营组 | `运营组` |

每个赛季只选择一个组别，写在 `group` 字段中。所有组别使用相同的学生模板，不把组别名称写进 `kind` 或 `roles`。

**职务只使用：队长、副队长、组长、项管、成员。**

| 实际情况 | 填写方法 |
| --- | --- |
| 普通队员 | `roles: [成员]` |
| 组长 | `roles: [组长]` |
| 副队长兼组长 | `roles: [副队长, 组长]` |
| 队长兼项管 | `roles: [队长, 项管]` |

网站会把组别和职务自动组合成“机械组组长”等展示文字，`roles` 中只填写职务本身。

同一职务不能重复填写；`成员` 不与其他职务并列；`队长` 和 `副队长` 不能同时填写。同一赛季只写一条记录；多个赛季的写法见下面的说明。

### 指导老师怎么填

老师也必须填写指导赛季，下面以 **`year: 2027`** 为单赛季示例。指导过多个赛季时，按下面的多赛季写法追加记录，不要把 `seasons` 留空或删除。

```markdown
---
kind: teacher
name: 老师姓名
image: /images/member_photo/老师姓名.jpg
affiliation: 机械工程学院
seasons:
  - year: 2027
---

## 个人简介

填写教师简介、研究方向或指导工作，没有正文时可删除这一节。
```

| 字段 | 填写方法 |
| --- | --- |
| `kind` | 指导老师固定写 `teacher` |
| `name` | 真实姓名，与文件名一致 |
| `image` | 头像路径；没有头像时删除这一整行 |
| `affiliation` | 实际所属学院，不填写学校名称 |
| `seasons` → `year` | 实际指导的赛季年份，如 `2027`；多赛季逐条填写 |

老师不填写学生的 `grade`、`group`、`roles`。网站会自动显示“指导老师”。

如果需要展示系、部门、职称或导师资格，可在资料区结尾的 `---` **之前**添加：

```yaml
department: 所属系或部门
titles:
  - 实际职称
  - 实际导师资格或校内职务
```

`department`、`titles` 均可省略；填写时按本人实际情况修改，不照抄示例。只填一条头衔时，保留一行 `-` 即可。

### 参加多个赛季怎么填

**一人仍然只交一份 `姓名.md`，不按年份拆成多份文件。** 在原来的 `seasons` 下，每个赛季添加一条以 `- year:` 开头的记录，保留原有记录。

下面的年份、组别和职务仅用于演示写法，不代表实际任职。只填写自己已经确认参与的赛季，不照抄演示中的后续年份。当前网站的真实成员资料仍只记录 2027 赛季。

#### 学生参加多个赛季

下面依次演示一个、两个、三个赛季。追加年份时，保留原有记录，新增当年的组别和职务。

**一个赛季：** 27 赛季是机械组成员。

```yaml
seasons:
  - year: 2027
    group: 机械组
    roles: [成员]
```

**两个赛季：** 在原有记录后，追加 28 赛季的机械组组长任职。

```yaml
seasons:
  - year: 2027
    group: 机械组
    roles: [成员]
  - year: 2028
    group: 机械组
    roles: [组长]
```

**三个赛季：** 再追加 29 赛季，转到电控组并兼任副队长、组长。

```yaml
seasons:
  - year: 2027
    group: 机械组
    roles: [成员]
  - year: 2028
    group: 机械组
    roles: [组长]
  - year: 2029
    group: 电控组
    roles: [副队长, 组长]
```

- 每个赛季都要完整填写 `year`、`group` 和 `roles`，即使组别或职务没变，也要重复填写；不会自动继承上一条。
- 换组或换职务时，写到对应的新赛季中，保留过去赛季的记录。原记录填错时，直接修正原记录，不为同一年新增第二条。
- `grade` 仍是最初的入学年份，不随参赛赛季改变；姓名、学院、头像、个人链接和正文仍共用原档案。
- 担任多个职务时，在同一赛季的 `roles` 中列出，不要把同一赛季拆成多条。

#### 老师指导多个赛季

老师同样保留一份档案。每个指导赛季只填写 `year`，不增加 `group`、`roles` 或 `grade`。

**一个赛季：** 指导过 27 赛季。

```yaml
seasons:
  - year: 2027
```

**两个赛季：** 继续指导 28 赛季，追加一条年份。

```yaml
seasons:
  - year: 2027
  - year: 2028
```

**三个赛季：** 又指导了 30 赛季，保留前两条并追加 2030。

```yaml
seasons:
  - year: 2027
  - year: 2028
  - year: 2030
```

第三个示例没有填写 2029，表示没有记录该赛季。赛季可以不连续，不要为了凑成连续年份补填未指导过的赛季。姓名、学院、部门、头衔、头像及主页链接继续写在同一份档案中。

#### 两类人员都要注意

- 整份资料只保留一个 `seasons:`，新增年份写在这个列表下面，不要再创建第二个同名字段。
- 年份仍写四位整数，不写 `27`、`2027–2029` 或逗号拼接的字符串；每年各占一条，建议按从早到晚的顺序填写。
- 同一个年份只能出现一次；没有参加或指导的赛季不填。
- 网站选定某个赛季后，显示该赛季对应的信息。选择“全部赛季”时，学生按最近一条记录归组，并保留历年职务；老师按已填写的年份筛选。
- 卡片赛季会合并连续年份，例如 `2027–2029`；不连续时分段显示，例如 `2027–2028、2030`。这是网站自动生成的，不用手写到资料里。

## 第三步：填写个人链接和介绍（可选）

学生和老师都可以填写 `links`。这里只列出主页、GitHub、GitCode 三个常用示例，按需保留。

| 填写的键名 | 网站显示 |
| --- | --- |
| `homepage` | 主页 |
| `github` | GitHub |
| `gitcode` | GitCode |

在资料区结尾的 `---` **之前**加入下面的内容，将示例地址换成真实主页：

```yaml
links:
  homepage: https://example.com
  github: https://github.com/你的用户名
  gitcode: https://xxxxxx.xxx/gitcodeID
```

- 有哪个链接就填哪个，没有链接时删除整个 `links`；同一键名不能重复。
- 填写以 `https://` 或 `http://` 开头的完整网页地址，不只填写账号，也不保留占位地址、空字符串或“无”。
- GitCode 示例中的 `xxxxxx.xxx` 和 `gitcodeID` 都要换成本人真实主页对应的域名和账号；用于研发看板对应时，域名须为 `gitcode.com`，不要填写仓库或组织列表链接。
- 其他网页链接也可填写，键名会作为按钮文字显示。

**GitCode 与研发看板：** 填好本人真实的 `links.gitcode` 后，看板按账号使用档案姓名、头像和个人介绍入口；同一账号只填在一份档案中。内容仓库推送并由 EO 重新部署后生效。

资料区结束后面的 Markdown 正文可以写：

- 学生：自我介绍、参与方向、实际工作、项目与比赛经历。
- 老师：个人简介、研究方向与指导工作。

没有个人介绍时，可以只保留开头的资料区。网站公开展示这些内容，请填写自己愿意公开的资料。

## 第四步：准备头像

1. 选择清晰的单人照，推荐 JPG、PNG 或 WebP，建议小于 5 MB。
2. 按真实姓名命名，例如 `张三.jpg` 或 `张三.png`。不要只改文件后缀来转换图片格式。
3. 资料里的 `image` 必须与实际文件名和后缀一致：

```yaml
image: /images/member_photo/张三.png
```

`image` 里不写电脑上的 `C:\...`、`/home/...` 路径，也不写 `public/`。没有头像时，删除整行 `image`，网站会使用默认头像。

## 第五步：检查后交给维护者

提交前逐项确认：

- [ ] 文件名是真实姓名，后缀为 `.md`，与 `name` 一致。
- [ ] 学生写 `kind: student`，老师写 `kind: teacher`。
- [ ] 学生和老师都填写了 `seasons`，每个实际参与的赛季各一条，同一年不重复，未预填未参与的年份。
- [ ] 学生的 `grade` 是真实入学年份，组别和职务使用上面的规定名称。
- [ ] 老师没有填写 `grade`、`group`、`roles`。
- [ ] 头像名称、后缀和 `image` 路径一致；无头像时已删除该行。
- [ ] 删除了不用的可选字段，没有填写空字符串、`null` 或“无”。
- [ ] 学院、头衔、链接和个人介绍均已换成实际内容。
- [ ] 没有添加学校字段 `university`、梯队字段，或旧字段 `type`、`role`、`time`、`advisor`。

把 **`姓名.md` 和头像原文件** 一起交给网站维护者。填写示例仅供参考，不会作为真实成员发布。

## 维护者处理

- 学生资料放入 `content/members/student/姓名.md`。
- 老师资料放入 `content/members/teacher/姓名.md`。
- 头像放入 `public/images/member_photo/`。
- 同一人只保留一份档案，当前指导老师韩博的赛季填写 `2027`。
- 在网站仓库同步内容后运行 `npm run members:check`；通过后推送内容仓库 `main`，EO 会自动构建部署。

完整字段规则见 [成员资料规范](../docs/成员资料规范.md)。
