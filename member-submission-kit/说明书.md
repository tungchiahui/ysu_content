# 燕鹰战队个人资料填写教程（27赛季）

这份教程用于填写网站“成员”页面的个人资料。学生和指导老师都提交 Markdown 文件与头像，当前统一填写 **2027 赛季**。

## 第一步：选择模板并改名

| 身份 | 使用的模板 | 参考示例 |
| --- | --- | --- |
| 学生 | [成员资料模板](成员资料模板.md) | [学生示例](填写示例-张三.md) |
| 指导老师 | [指导老师资料模板](指导老师资料模板.md) | [老师示例](填写示例-指导老师.md) |

1. 下载或复制对应模板，用记事本、VS Code 等纯文本编辑器打开。
2. 把文件改成自己的真实姓名，例如 `张三.md`。
3. 保存为 UTF-8 编码，确认后缀是 `.md`，不是 `.md.txt`，也不要另存为 Word 或 PDF。

一人一份文件。文件名必须与下面的 `name` 完全一致；不以“张三”“老师姓名”等示例名字提交。

## 第二步：填写开头的资料区

文件最上方用两行 `---` 包围的部分是资料区；结束的 `---` 后面可以写个人介绍。保留英文键名，只修改右侧的内容。

- 冒号使用英文 `:`，冒号后留一个空格。
- 缩进使用空格，每一层两个空格，不要使用 Tab。
- 保留两行 `---`，不要删除 `seasons` 下方的短横线。
- 年份写四位整数，不加引号。**27赛季写 `2027`，不要写 `27` 或 `2027赛季`。**

### 学生怎么填

下面是一份普通队员的完整资料示例，可以复制后修改：

```markdown
---
kind: student
name: 张三
image: /images/member_photo/张三.jpg
affiliation: 机械工程学院
grade: 2026
seasons:
  - year: 2027
    group: 机械组
    roles: [成员]
---

## 个人介绍

这里写自己的学习方向、参与的工作或个人兴趣。

## 项目与比赛经历

- 按自己的实际经历填写，没有相关经历时可删除这一节。
```

| 字段 | 填写方法 |
| --- | --- |
| `kind` | 学生固定写 `student` |
| `name` | 真实姓名，与文件名一致 |
| `image` | 头像路径，写法见第四步；没有头像时删除这一整行 |
| `affiliation` | 实际所属学院，不填写学校名称 |
| `grade` | 自己的入学年份；示例中的 `2026` 要按实际情况修改 |
| `seasons` → `year` | 当前只填写 `2027`，不是入学年份 |
| `seasons` → `group` | 从下面五个组别中选一个 |
| `seasons` → `roles` | 按实际职务填写列表，普通队员写 `[成员]` |

**组别只使用以下五种名称：**

| 组别 | `group` 的填写值 |
| --- | --- |
| 机械组 | `机械组` |
| 电控组 | `电控组` |
| 硬件组 | `硬件组` |
| 算法组 | `算法组` |
| 运营组 | `运营组` |

每个赛季只选择一个组别，写在 `group` 字段中。所有组别使用相同的学生模板，不把组别名称写进 `kind` 或 `roles`。

**职务只使用：队长、副队长、组长、项管、成员。**

| 实际情况 | 填写方法 |
| --- | --- |
| 普通队员 | `roles: [成员]` |
| 组长 | `roles: [组长]` |
| 副队长兼组长 | `roles: [副队长, 组长]` |
| 队长兼项管 | `roles: [队长, 项管]` |

网站会把组别和职务自动组合成“机械组组长”等展示文字，`roles` 中只填写职务本身。

同一职务不能重复填写；`成员` 不与其他职务并列；`队长` 和 `副队长` 不能同时填写。当前只交一条 2027 赛季记录，后续赛季由维护者按实际任职追加。

### 指导老师怎么填

老师也填写赛季，**当前只写 `year: 2027`**，不要把 `seasons` 留空或删除。

```markdown
---
kind: teacher
name: 老师姓名
image: /images/member_photo/老师姓名.jpg
affiliation: 机械工程学院
seasons:
  - year: 2027
---

## 个人简介

填写教师简介、研究方向或指导工作，没有正文时可删除这一节。
```

| 字段 | 填写方法 |
| --- | --- |
| `kind` | 指导老师固定写 `teacher` |
| `name` | 真实姓名，与文件名一致 |
| `image` | 头像路径；没有头像时删除这一整行 |
| `affiliation` | 实际所属学院，不填写学校名称 |
| `seasons` → `year` | 当前只填写 `2027` |

老师不填写学生的 `grade`、`group`、`roles`。网站会自动显示“指导老师”。

如果需要展示系、部门、职称或导师资格，可在资料区结尾的 `---` **之前**添加：

```yaml
department: 所属系或部门
titles:
  - 实际职称
  - 实际导师资格或校内职务
```

`department`、`titles` 均可省略；填写时按本人实际情况修改，不照抄示例。只填一条头衔时，保留一行 `-` 即可。

## 第三步：填写个人链接和介绍（可选）

学生和老师都可以添加公开主页、GitHub、GitCode、Bilibili 等链接。在资料区结尾的 `---` **之前**加入，例如：

```yaml
links:
  homepage: https://example.com
  github: https://github.com/你的用户名
  gitcode: https://gitcode.com/你的用户名
```

只保留自己实际使用的链接，把示例地址改为真实地址；没有链接时，不添加 `links`。链接要以 `https://` 或 `http://` 开头。其他常用键包括 `bilibili`、`blog`、`google-scholar`。

资料区结束后面的 Markdown 正文可以写：

- 学生：自我介绍、参与方向、实际工作、项目与比赛经历。
- 老师：个人简介、研究方向与指导工作。

没有个人介绍时，可以只保留开头的资料区。网站公开展示这些内容，请填写自己愿意公开的资料。

## 第四步：准备头像

1. 选择清晰的单人照，推荐 JPG、PNG 或 WebP，建议小于 5 MB。
2. 按真实姓名命名，例如 `张三.jpg` 或 `张三.png`。不要只改文件后缀来转换图片格式。
3. 资料里的 `image` 必须与实际文件名和后缀一致：

```yaml
image: /images/member_photo/张三.png
```

`image` 里不写电脑上的 `C:\...`、`/home/...` 路径，也不写 `public/`。没有头像时，删除整行 `image`，网站会使用默认头像。

## 第五步：检查后交给维护者

提交前逐项确认：

- [ ] 文件名是真实姓名，后缀为 `.md`，与 `name` 一致。
- [ ] 学生写 `kind: student`，老师写 `kind: teacher`。
- [ ] 学生和老师都填写了 `seasons`，当前只有一条 `year: 2027`。
- [ ] 学生的 `grade` 是真实入学年份，组别和职务使用上面的规定名称。
- [ ] 老师没有填写 `grade`、`group`、`roles`。
- [ ] 头像名称、后缀和 `image` 路径一致；无头像时已删除该行。
- [ ] 删除了不用的可选字段，没有填写空字符串、`null` 或“无”。
- [ ] 学院、头衔、链接和个人介绍均已换成实际内容。
- [ ] 没有添加学校字段 `university`、梯队字段，或旧字段 `type`、`role`、`time`、`advisor`。

把 **`姓名.md` 和头像原文件** 一起交给网站维护者。填写示例仅供参考，不会作为真实成员发布。

## 维护者处理

- 学生资料放入 `content/members/student/姓名.md`。
- 老师资料放入 `content/members/teacher/姓名.md`。
- 头像放入 `public/images/member_photo/`。
- 同一人只保留一份档案，当前指导老师韩博的赛季填写 `2027`。
- 在网站仓库同步内容后运行 `npm run members:check`；通过后推送内容仓库 `main`，EO 会自动构建部署。

完整字段规则见 [成员资料规范](../docs/成员资料规范.md)。
