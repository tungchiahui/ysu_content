# 燕鹰战队人员资料填写说明

学生使用 `成员资料模板.md`，指导老师使用 `指导老师资料模板.md`。示例文件仅说明格式，不会出现在网站成员列表中。

## 提交哪些文件

提交姓名一致的资料和头像，例如 `张三.md` 与 `张三.jpg`。使用记事本、VS Code 等纯文本编辑器，保存为 UTF-8；不要保存成 Word 或 `张三.md.txt`。没有照片时可省略 `image`，网站使用默认头像。

资料开头两行 `---` 之间是 YAML frontmatter；保留英文键名，只修改值。冒号后保留一个空格，缩进使用两个空格，不要使用 Tab。两行 `---` 之后是可选的 Markdown 个人介绍。

## 学生资料

```yaml
---
kind: student
name: 张三
image: /images/member_photo/张三.jpg
affiliation: 电气工程学院
grade: 2026
seasons:
  - year: 2027
    group: 算法组
    roles: [成员]
links:
  homepage: https://example.com
---
```

- `grade` 是入学年份，`year` 是比赛赛季，均使用不加引号的四位整数；2026 级可以参加 2027 赛季。
- 网站成员资料中赛季仅显示年份，例如 `2027`；顶部筛选显示为 `27赛季`，填写资料时仍使用四位整数。
- `group` 仅限：机械组、电控组、硬件组、算法组、运营组，每个赛季选一个。运营组使用相同模板，参考 [运营组填写示例](填写示例-运营组.md)。
- `roles` 是职务列表，仅限：队长、副队长、组长、项管、成员。
- 普通队员填写 `[成员]`；兼任副队长和组长时填写 `[副队长, 组长]`。组长按组别显示为“算法组组长”“运营组组长”等名称。
- 职务不能重复；“成员”不与其他职务并列，队长和副队长不能同时填写。
- 同一人每个赛季只写一条记录；以后更换组别或职务，在 `seasons` 中追加下一赛季，保留旧记录。

```yaml
seasons:
  - year: 2027
    group: 算法组
    roles: [成员]
  - year: 2028
    group: 算法组
    roles: [组长]
```

## 指导老师资料

```yaml
---
kind: teacher
name: 老师姓名
image: /images/member_photo/老师姓名.jpg
affiliation: 所属学院
department: 所属系或部门
titles:
  - 教授
  - 博士生导师
seasons:
  - year: 2027
links:
  homepage: https://example.com
---
```

- `department`、`titles` 可省略；`titles` 填写职称、导师资格或校内职务。
- 老师不填写 `grade`，赛季记录中不填写 `group` 或 `roles`。
- `seasons: []` 或省略 `seasons` 表示不限定赛季，会在所有赛季筛选中展示。填写具体年份时，只在对应赛季或“全部赛季”展示。
- 填写教师实际所属学院。当前指导老师为燕山大学机械工程学院韩博，资料依据学校教师主页；未知指导赛季不推断填写。

## 可选字段和链接

`image`、`links`、教师的 `department`、`titles` 没有内容时直接删除对应字段，不填写 `null`、空字符串或“无”。学生必须有 `grade` 和至少一条完整赛季记录。

`links` 使用公开的 HTTP/HTTPS 地址，常用键为 `homepage`、`github`、`gitcode`、`bilibili`、`blog`、`google-scholar`。没有公开链接时删除整个 `links` 字段。不要使用旧键 `home-page`。

学生与指导老师均不填写学校字段 `university`；保留学院字段 `affiliation`。不再使用旧字段 `type`、`role`、`time`、`advisor`，也没有梯队字段。正文可介绍历史经历，但当前职务以对应赛季记录为准。

## 头像与正文

头像推荐清晰的单人照，使用 JPG、PNG 或 WebP，建议小于 5 MB。文件后缀必须与 `image` 一致。头像交由维护者放入 `public/images/member_photo/`；frontmatter 只写 `/images/member_photo/文件名`。

正文可填写自我介绍、技术方向、项目和比赛经历。网站公开可见，只填写愿意公开的信息。

## 交给维护者

把 `.md` 和头像原文件一起交给网站维护者；不要修改示例后仍以“张三”命名。待战队确定统一收集方式后，再补充收集入口；旧站的资料收集链接已不再使用。

维护者将学生档案放入 `content/members/student/`，老师放入 `content/members/teacher/`，文件名必须与 `name` 完全一致。一人一份档案，跨赛季经历写在同一文件中。

维护者在网站仓库同步内容后运行 `npm run members:check`。开发和正式构建也会自动检查字段、赛季、组别、职务、姓名冲突和头像文件。填写错误会给出文件名及具体字段；修正后再提交。

完整字段规范见 `docs/成员资料规范.md`。
